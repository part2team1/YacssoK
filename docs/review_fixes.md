# 데이터·웹 검증과 실행 안내

## 데이터 다시 내보내기

`export_yolo.py`는 한 버전의 새 출력 폴더를 완성한 다음 기존 생성 폴더와 교체합니다. 실패하면 이전 출력을 유지합니다. 원본 이미지·정답·클래스 목록·분할 파일과 출력 경로가 겹치거나 train·val 사진 이름이 겹치면 중단합니다. 사용 중인 RFS 설정 파일도 새 분할에 맞춰 다시 생성합니다.

## 모델 합치기

`make_submission.py --exp A B`는 두 실험의 `label_idx → category_id`가 완전히 같을 때만 실행합니다. 서로 다른 클래스 목록은 별도로 제출하거나 공통 번호표로 변환하는 절차를 먼저 정해야 합니다. 테스트 사진 목록·image_id·라벨도 CSV를 만들기 전에 검사합니다.

## 같은 기준으로 점수 비교하기

`selection_metrics.json`은 모델 선택용 재평가 결과이며 기존 학습 결과 `metrics.json`은 유지합니다. 기존 가중치를 평가하므로 아래 명령은 학습을 하지 않습니다.

```bash
uv run python scripts/evaluate.py --exp EXP_A --val-config configs/COMMON.yaml --for-selection
uv run python scripts/evaluate.py --exp EXP_B --val-config configs/COMMON.yaml --for-selection
```

`EXP_A`, `EXP_B`는 실제 실험 이름, `configs/COMMON.yaml`은 팀이 정한 같은 검증 사진·정답·클래스 목록을 가리키는 설정으로 바꿉니다. 모델과 검증 정답의 클래스 번호가 다르면 중단합니다.

파이프라인에서는 `--selection-config configs/COMMON.yaml`을 명시하면 후보를 같은 데이터로 재평가합니다. 공통 평가의 지문과 실제 가중치가 맞는 점수만 순위를 정합니다. 공통 평가가 없거나 기준이 다르면 자동 선택을 중단합니다. 보고서 표와 보조 지표도 선택에 사용한 평가 결과를 표시합니다.

## 같은 이름의 실험 다시 실행하기

새 결과에는 설정·정답·분할·클래스 목록·사진 메타데이터·코드의 지문이 기록됩니다. 사진 메타데이터 비교는 모든 학습 이미지 바이트의 동일성 보증을 뜻하지 않습니다. OCR은 연결된 탐지 모델·설정·각인 정보표의 내용도 함께 검사합니다.

완료 여부만으로 과거 결과를 새 계획에 재사용하지 않습니다. 지문이 없거나 다르고, 혹은 미완료 파일만 남아 있으면 중단합니다. 새 실험 이름을 쓰는 방법을 우선 사용하세요. 기존 결과를 같은 경로에 다시 학습할 의도가 있을 때만 `run_matrix.py --force`를 명시합니다. 이 옵션은 재학습을 실행할 수 있습니다.

## 웹

- 테스트 화면은 사진·신뢰도·초기화가 바뀌면 이전 요청의 결과를 표시하지 않습니다. 세션별 상태를 사용하며 다른 사용자의 작업을 지우지 않습니다.
- 앱 데모는 다운로드용 CSV를 만들지 않습니다. 테스트 화면의 CSV 원본은 엔진 전용 임시 폴더에 저장하고 다음 저장 시 1시간이 지난 파일을 정리합니다. 프로세스가 정상 종료되거나 엔진이 해제되면 임시 폴더도 정리됩니다. Gradio의 다운로드 캐시는 별도 관리합니다.
- 기존 `app/demo.py --share`도 `PILL_USERNAME`, `PILL_PASSWORD` 환경변수를 요구하며, 대회 테스트 사진을 자동 예시로 공개하지 않습니다.
- 현재 앱 데모·테스트 통합 진입점은 [web_portal.md](web_portal.md)에 있습니다.
